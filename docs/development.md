## Local checks

Run `scripts/dev/verify.sh affected` for working-tree changes. `affected --base <git-ref>` also checks committed changes against that base. Explicit modes are `packages`, `app`, `release-tools`, and `all` (see `scripts/dev/verify.sh` for the current list). The wrapper records the commit, dirty state, platform, commands, pass/fail counts and elapsed time under `build/verify/<UTC timestamp>-<pid>/`. Exit 2 means a missing prerequisite or invalid selection; other nonzero exits are failing checks. It never installs global tools or enables live provider tests.

`packages` tests the local Swift packages (the inference package, CalendarApple and EventKitSource); the engine is tested in the `timetug-shared` repository (and the connectors in `calendar-connectors`), not here. `app` regenerates the Xcode project before app tests. `release-tools` runs shell suites (including the licence-notice copy script's), Python release tests, website Node tests, workflow checks and repository contracts. `all` runs every package, app and release-tool check. App-only code routes to app; workflow/release/site code routes to release tools; documentation routes to repository contracts; unknown paths route to all. Linux and Windows portability of the engine is proven in `timetug-shared`'s CI, outside this wrapper; the [macOS UI checklist](manual-tests/macos-checklist.md) is manual. The wrapper's output says so.

When changing an import or dependency rule, update `scripts/ci/check-architecture.sh` and `scripts/ci/tests/test-check-architecture.sh` together. The rules for the engine's crates live in the same-named scripts in `timetug-shared`. The one dependency pin, `timetug-shared`, moves only through `scripts/ci/bump-pin.sh timetug-shared X.Y.Z` and is checked by `scripts/ci/check-shared-pins.py`.

**Building needs no Rust toolchain.** `TimeTugKit` ships the engine as the prebuilt `TimeTugEngineFFI.xcframework` (a static library for macOS arm64 and x86_64), which SwiftPM downloads at the pinned version; Xcode and the app need nothing else. A Rust toolchain is needed only for local library work: to try an unreleased engine change, build that checkout's XCFramework (`scripts/dev/build-xcframework.sh` in `timetug-shared`, with the toolchain in its `rust-toolchain.toml`) and run `scripts/dev/use-local-library.sh timetug-shared <checkout path>`, which points the app and the local packages at it (never commit its output; `--restore` undoes it). The licence notices that the build copies into the app (`Contents/Resources/Licenses/`, by the `Copy licence notices` build phase running `scripts/ci/copy-licence-notices.sh`) come from the resolved XCFramework, or from the local checkout's `build/TimeTugEngineFFI.xcframework`; the build fails when one is missing.

Prerequisites: Swift 6/Xcode for packages (no Rust), XcodeGen and xcodebuild for app, Python 3 with pinned `scripts/ci/requirements-test.txt`, Node for website tests, and Bash. CI installs the Python prerequisites in a virtual environment. No live calendar test flags are set by the wrapper. Run live tests only from the [operations runbook](development/runbooks/operations.md) with the required account and explicit task authorization.

`Apps/macOS/project.yml` owns generated app and widget Info.plist properties, including privacy descriptions, Sparkle metadata and OAuth substitutions. After editing it, run XcodeGen twice and verify no second-generation tracked diff appears. Keep checked-in Info.plists in sync. `*.xcodeproj` is intentionally ignored.

The `Code index` workflow publishes the `qindex` artifact. `scripts/dev/qindex.py` must stay identical to the shared index skill's script; keep the pinned libraries in `.github/workflows/index.yml` compatible with that skill when either changes. The shared agent rules describe local index use.

## Focused lint

ShellCheck 0.11.0 is the pinned shell linter for new verification scripts. Run `scripts/dev/lint.sh` when editing them; it requires exactly ShellCheck 0.11.0. A 2026-09-26 baseline scan of every `scripts/**/*.sh` found seven SC2016 notes in `scripts/ci/build-release.sh` and the Google/Microsoft OAuth-config shell tests (intentional literal shell expressions in fixtures). The focused lint command passes without suppressing warnings globally. Expand lint coverage after resolving those seven notes in a scoped change. The CI release-tooling job runs executable tests and syntax checks.
